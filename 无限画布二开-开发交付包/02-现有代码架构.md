# 02 · 现有代码架构（基线：basketikun/infinite-canvas）

> 基线版本：`v0.20.0506`，commit `9f2bd9f`（2026-10-20）。以下路径都以仓库根目录为起点，均已对照源码核实。
> 开发前先通读根目录 `AGENTS.md`，那是原作者对 AI 开发的约束，本项目继续沿用（例外见本文第 9 节）。

## 1. 仓库结构

```
infinite-canvas/
├── web/                 # 主应用（唯一的产品代码）：Vite 7 + React 19 + TS
├── canvas-agent/        # 本地 Agent：Node 服务，MCP 方式把画布暴露给 Codex / Claude Code
├── canvas-proxy/        # 本地转发代理（npx @basketikun/canvas-proxy），解决浏览器直连 CORS
├── plugins/
│   ├── canvas/          # 画布节点插件：sdk/、template/、html/markdown/svg/panorama/sticky-note 等官方插件
│   └── infinite-canvas/ # Codex app 插件
├── docs/                # 文档站（Next + fumadocs），内容在 docs/content/docs/**.mdx
├── AGENTS.md            # AI 开发规范（必读）
├── CHANGELOG.md / VERSION
├── Dockerfile           # 两阶段：bun 构建 web → nginx 托管静态文件（端口 3000）
├── docker-compose.yml / nginx.conf / render.yaml / vercel.json
```

**当前没有任何后端。** Docker 镜像只托管静态文件，AI 请求由浏览器直接发到用户配置的接口。

## 4. 核心数据模型

### 4.1 画布（`web/src/types/canvas.ts`）

```ts
export enum CanvasNodeType { Image = "image", Text = "text", Config = "config", Video = "video", Audio = "audio", Group = "group" }
export type CanvasNodeTypeId = CanvasNodeType | (string & {});   // 插件节点用 "<pluginId>:<name>"

export type CanvasNodeData = {
  id: string; type: CanvasNodeTypeId; title: string;
  position: { x: number; y: number }; width: number; height: number;
  metadata?: CanvasNodeMetadata;   // 所有业务字段都在这里（见下）
};
export type CanvasConnection = { id: string; fromNodeId: string; toNodeId: string };
```

`CanvasNodeMetadata` 的常用字段：

- 文本：`content`
- 生成配置：`prompt`、`composerContent`（富文本提示词，用 `@[node:<id>]` 引用上游节点）、`generationMode`（text/image/video/audio）、`model`、`size`、`quality`、`count`、`seconds`、`references`
- 结果：`status`（idle/loading/success/error）、`errorDetails`、`images[]`（批量结果）、`primaryImageId`、`storageKey`、`naturalWidth/Height`
- 视频异步任务：`videoTaskId`、`videoTaskProvider`
- 分组：`groupId`

### 4.2 项目（`web/src/stores/canvas/use-canvas-store.ts`）

```ts
export type CanvasProject = {
  id; title; createdAt; updatedAt;
  nodes: CanvasNodeData[]; connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[]; activeChatId: string | null;
  backgroundMode: "dots" | "lines" | "blank"; showImageInfo: boolean;
  viewport: { x; y; k };
};
```

- 整个项目列表以一个 JSON 存在 IndexedDB 的 `infinite-canvas:canvas_store` 键下，写入有 400ms 防抖。
- 图片二进制存在 localforage 的 `image_files` 实例，键名 `image:<nanoid>`；视频和音频走 `services/file-storage.ts`。节点只保存 `storageKey`。
- 导出格式在 `types/canvas-export.ts` + `lib/canvas/canvas-export.ts`：zip 包内含 `projects.json`（`{ app: "infinite-canvas", version: 3, projects: [{ project, files }] }`）和 `projects/<id>/files/*`。

### 4.3 渠道与模型配置（`web/src/stores/use-config-store.ts`）

```ts
export type ModelChannel = { id; name; baseUrl; apiKey; apiFormat: "openai" | "gemini"; models: ChannelModel[] };
export type ChannelModel = { name: string; capability: "image" | "video" | "text" | "audio"; script?: string };
export type AiConfig = {
  channelMode: "remote" | "local";   // ⚠️ 目前恒为 "local"，"remote" 是预留但未实现的分支，正好可用来接平台网关
  channels: ModelChannel[];
  imageModel / videoModel / textModel / audioModel: string;   // 格式 "<channelId>::<modelName>"
  systemPrompt: string;              // 会被 withSystemPrompt() 拼到每次提示词前面
  quality, size, count, videoSeconds, ... ;
  proxyEnabled: boolean; proxyUrl: string;   // 本地代理
};
```

关键函数：

- `resolveModelRequestConfig(config, "<channelId>::<model>")`：根据模型找到所属渠道，返回带 `baseUrl / apiKey / apiFormat` 的请求配置。
- `buildApiUrl(baseUrl, path)`：自动补 `/v1`，再经过 `withLocalProxy()`。
- `resolveModelScript()`：如果模型配置了自定义调用脚本，就走 `services/api/model-plugin.ts` 的 `runModelPlugin()`（在浏览器沙箱里执行用户写的 JS）。
- 配置用 zustand persist 存在 `localStorage` 的 `infinite-canvas:ai_config_store`，**API Key 明文存在浏览器**。

## 5. AI 调用链路（二开计费的切入点）

所有生成最终都落到 `services/api/` 下的 4 个文件。OpenAI 格式下，前端实际调用的上游接口**只有 8 个**：

| 能力 | 函数 | 上游接口 | 请求体 |
|---|---|---|---|
| 模型列表 | `fetchImageModels` / `fetchChannelModels`（image.ts） | `GET /v1/models` | — |
| 文生图 | `requestGeneration`（image.ts:694） | `POST /v1/images/generations` | JSON：model、prompt、n、quality、size、background、output_format；返回 b64 |
| 图生图 / 编辑 / 蒙版 | `requestEdit`（image.ts:754） | `POST /v1/images/edits` | multipart：model、prompt、n、image[]、mask 等 |
| 文本（流式） | `requestImageQuestion` → `requestStreamingResponse`（image.ts:472） | `POST /v1/responses`（`stream: true`，SSE） | Responses API |
| 视频创建 | `createVideoGenerationTask`（video.ts:72） | `POST /v1/videos` | multipart：model、prompt、seconds、size、ratio、mode、first_frame/last_frame/image[]、video[]、audio[] |
| 视频轮询 | `pollVideoGenerationTask`（video.ts:82） | `GET /v1/videos/{id}` | 返回 status / url |
| 视频下载 | 同上 | `GET /v1/videos/{id}/content` | blob |
| 语音 | `requestAudioGeneration`（audio.ts:23） | `POST /v1/audio/speech` | JSON：model、input、voice、response_format、speed |

请求头统一由各文件里的 `aiHeaders(config)` 生成：`Authorization: Bearer <apiKey>`。

**调用方**（都直接 import 上面这些函数）：

- `pages/canvas/project.tsx`：画布节点生成。主入口是 `handleGenerateNode(nodeId, mode, prompt)`（第 2326 行附近），通过 `generateNodeRef` 暴露给 Agent 和插件；它内部用 `buildNodeGenerationContext()`（`components/canvas/canvas-node-generation.ts`）汇总上游节点的文本和参考图。重试、裁剪、蒙版、扩图等也在这个文件里。
- `pages/image/index.tsx`、`pages/video/index.tsx`：工作台。
- `pages/canvas/hooks/use-plugin-host.tsx`：插件通过宿主拿到的 `ai.generateImage / generateVideo / generateText`。

**结论：** 只要让"平台渠道"的 `baseUrl` 指向自建的 OpenAI 兼容网关，并实现上面 8 个接口，前端生成逻辑几乎不用改，计费、品牌注入、Key 托管都能在服务端完成。

## 6. 画布指令集（模板功能的基础）

`web/src/lib/canvas/canvas-agent-ops.ts` 定义了一套结构化画布操作，本地 Agent 和插件都在用：

```ts
export type CanvasAgentOp =
  | { type: "add_node"; id?; nodeType?; title?; position?; x?; y?; width?; height?; metadata? }
  | { type: "update_node"; id; patch?; metadata? }
  | { type: "delete_node"; id?; ids?; nodeType? }
  | { type: "delete_connections"; id?; ids?; all? }
  | { type: "connect_nodes"; id?; fromNodeId; toNodeId }
  | { type: "set_viewport"; viewport }
  | { type: "select_nodes"; ids }
  | { type: "run_generation"; nodeId; mode?; prompt? };
```

- 纯函数 `applyCanvasAgentOps(snapshot, ops)` 负责应用这些操作。
- 画布页面里的 `useAgentBridge()`（`pages/canvas/hooks/use-agent-bridge.ts`）提供 `applyAgentOps(ops)`：应用操作、记录撤销快照，并对 `run_generation` 调用 `generateNodeRef.current(...)` 真正发起生成。

**行业模板 = 一组带变量的 `CanvasAgentOp[]`**，实例化时替换变量、重映射 id，再交给 `applyAgentOps` 执行。这样模板功能不需要新的画布机制。

## 7. 插件系统

- 类型定义在 `web/src/types/canvas-plugin.ts`：`CanvasPlugin { id, name, version, nodes: CanvasNodeDefinition[], setup? }`。
- 节点定义可以提供 `Content`、`Panel`、`toolbar`、`resource`（作为上游时输出什么），也可以复用内置生成面板（`useBuiltinPanel`）。
- 运行时上下文 `CanvasNodeContext` 提供：`getUpstream / getDownstream`、`applyOps`、`emit / on`、`ai.generateImage / generateVideo / generateText`、`storage`。
- 注册表在 `lib/canvas/node-registry.ts`，加载器是 `lib/canvas/plugin-loader.ts`，状态在 `stores/canvas/use-plugin-store.ts`。
- 官方插件注册表默认指向 jsDelivr：`PLUGIN_REGISTRY_URL`（`constant/env.ts`），可以用 `VITE_PLUGIN_REGISTRY_URL` 覆盖。SDK 和模板在 `plugins/canvas/sdk`、`plugins/canvas/template`。
- 插件走 `ctx.ai.*`，最终也调用第 5 节那些函数，所以**插件生成同样会经过网关计费**。

`AGENTS.md` 其余规则继续遵守。以下几条与二开方向冲突，请在第一个 PR 里同步修改 `AGENTS.md`：

1. 原文"外部服务请求统一放在 `web/src/services/api/`，由浏览器前端直连，**不假设存在项目后端**"。
   改为：前端请求仍统一放在 `services/api/`，但新增 `server/` 后端，平台渠道走 `/api/gateway/v1/*`。

## 10. 已知的技术债和坑

- `pages/canvas/project.tsx` 有 3476 行，所有生成和交互逻辑都在里面。改它时只做最小改动，不要顺手重构（AGENTS.md 也这样要求）。
- 渠道支持 `gemini` 格式和自定义脚本（`runModelPlugin`），这两条路径会绕过 OpenAI 接口。平台渠道要固定为 `apiFormat: "openai"`、不带 `script`。
- 媒体结果以 b64 / dataURL 返回后存进 IndexedDB。网关必须保持相同的返回格式，否则前端解析（`parseImagePayload`）会失败。
- 作者声明不兼容旧数据。fork 后要定期从上游合并，所以新增代码尽量放在新目录和新文件里，减少对原文件的侵入。
- 原项目 README 要求"二次开发保留原作者信息和前端页面标识"。MIT 协议本身只要求保留版权声明；页面上保留"基于 infinite-canvas"的标识，并在关于页附上原项目链接和 LICENSE。
