# 03 · 技术方案

> 配套文件：`specs/schema.sql`（数据库表结构）、`specs/openapi.yaml`（业务 API）、`specs/template.schema.json` 与 `specs/template-example.json`（模板格式）。
> 本文是实现依据。与上述文件冲突时以 `specs/` 为准，并请指出冲突。

## 1. 总体架构

```
浏览器（web/，React）
 │
 ├─ /api/*                → server/ 业务 API（账号、工作区、品牌、模板、计费、上传）
 │
 └─ /api/gateway/v1/*     → server/ 模型网关（OpenAI 兼容，8 个接口）
                               │ 鉴权 → 选模型 → 估价 → 品牌注入 → 审核 → 冻结点数
                               │ → 转发上游 → 结算 / 退款 → 结果归档
                               ▼
                         上游模型供应商（OpenAI 兼容的中转或官方接口，Key 加密存储）

server/ ── PostgreSQL 16（业务数据、账本）
        └─ S3 兼容对象存储（MinIO / 阿里云 OSS）：品牌素材、模板封面、生成结果归档
```

部署时用 nginx（或任意反向代理）把 `/api/` 转发到 server，其余路径走 web 静态文件。前后端同域，所以 Cookie 直接可用，也没有 CORS 问题。

### 两种运行模式

| 模式 | 开关 | 行为 |
|---|---|---|
| 平台模式（SaaS） | web：`PLATFORM_API_BASE=/api`；server：`BILLING_ENABLED=true` | 需要登录；内置"平台"渠道；网关计费 |
| 私有化 · 不计费 | server：`BILLING_ENABLED=false` | 网关照常转发、照常记录用量，但不扣点、不拦截 |
| 纯前端（原版行为） | web：`PLATFORM_API_BASE` 留空 | 不显示登录、品牌、模板、计费入口，和上游原项目一致 |

`PLATFORM_API_BASE` 沿用原项目的运行期配置机制：`constant/runtime-config.ts` 读取 `window.__RUNTIME_CONFIG__`，由 `web/docker-entrypoint.sh` 注入。

## 2. 后端选型

| 项 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Bun 1.3**（与 web 一致） | 统一工具链；内置 `Bun.password`（argon2id） |
| Web 框架 | **Hono 4** | 轻量，原生支持流式响应，适合做代理 |
| ORM | **Drizzle ORM** + drizzle-kit 迁移 | 类型安全，SQL 透明 |
| 校验 | **zod** | 请求校验；前后端可以共享 schema |
| 数据库 | **PostgreSQL 16** | 账本需要事务和行锁 |
| 对象存储 | **S3 兼容**（`@aws-sdk/client-s3`），开发用 MinIO | 可以对接阿里云 OSS、腾讯云 COS |
| 定时任务 | MVP 用进程内 `setInterval` 扫描器 | 不引入 Redis；多实例部署时改用 `pg_try_advisory_lock` 保证同一时刻只有一个实例在扫 |
| 加密 | AES-256-GCM（`node:crypto`），主密钥来自 `APP_SECRET` | 加密存储上游 API Key |

## 3. 账号、会话与权限

- **注册**：`POST /api/auth/register {email, password, name}`。密码至少 8 位，用 `Bun.password.hash(pw, "argon2id")` 存储。注册时在同一个事务里创建用户、个人工作区（owner）、套餐点数桶（体验点数，数量取 `SIGNUP_BONUS_CREDITS`）。
- **会话**：登录成功后生成 32 字节随机 token，存它的 sha256 到 `sessions` 表，明文放进 Cookie `ic_session`（`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=30 天`）。剩余有效期少于 15 天时自动续期。
- **CSRF**：所有非 GET 请求都校验 `Origin` 是否等于 `APP_ORIGIN`。
- **当前工作区**：前端在每个请求上带 `X-IC-Workspace: <workspaceId>`。服务端校验当前用户是这个工作区的成员；缺少这个头时使用 `users.last_workspace_id`。
- **角色**：

| 能力 | owner | admin | member |
|---|---|---|---|
| 生成、使用模板和品牌 | ✓ | ✓ | ✓ |
| 编辑品牌、发布团队模板 | ✓ | ✓ | 需要品牌的编辑权限 |
| 邀请成员、设置成员上限、查看全员用量 | ✓ | ✓ | ✗ |
| 充值、兑换码、删除工作区、转让 | ✓ | ✗ | ✗ |

- **邀请**：`POST /api/workspaces/:id/invites` 生成邀请链接（token 有效期 7 天）。被邀请人登录后调用 `POST /api/invites/:token/accept`。MVP 不发邮件，前端直接展示链接让管理员复制。
- **API Token**（可选，给开发者在其他工具里调用网关用）：`ick_` 前缀加 32 字节随机数，只存哈希，归属某个工作区。
- **平台管理员**：`users.is_platform_admin = true` 的用户可以进入 `/admin`，管理供应商、模型、定价、官方模板，给工作区加点，生成兑换码。

## 4. 模型网关（核心）

### 4.1 接口

路径前缀是 `/api/gateway/v1`。请求和响应格式**与 OpenAI 完全一致**，这样前端现有代码不用改解析逻辑。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/models` | 返回当前工作区可用的平台模型，格式 `{object:"list", data:[{id, object:"model", owned_by:"platform", capability, price_hint}]}` |
| POST | `/images/generations` | 文生图 |
| POST | `/images/edits` | 图生图、编辑、蒙版（multipart） |
| POST | `/responses` | 文本，支持 `stream: true`，用 SSE 透传 |
| POST | `/videos` | 创建视频任务（multipart），返回**网关自己的任务 id**（`vt_…`） |
| GET | `/videos/:id` | 查询任务状态。终态时触发结算或退款 |
| GET | `/videos/:id/content` | 下载视频（从归档或上游流式转发） |
| POST | `/audio/speech` | 语音合成，返回音频二进制 |

### 4.2 鉴权与上下文

- `Authorization: Bearer ick_…` 按 API Token 鉴权；其他情况（包括前端平台渠道发来的占位值 `Bearer platform`）都改用 Cookie 会话鉴权。
- 前端额外发送这几个头，都可选：
  - `X-IC-Workspace`
  - `X-IC-Brand`：品牌 id，或 `none` 表示本次不套用
  - `X-IC-Project`：画布项目 id
  - `X-IC-Node`：节点 id
  - `X-IC-Source`：`canvas` / `image-workbench` / `video-workbench` / `plugin` / `agent`

  它们会写进 `generation_jobs`，用于统计用量和展示生成记录。
- 品牌解析顺序：请求头 `X-IC-Brand` → 工作区默认品牌 → 不套用。如果品牌设置了 `enforced = true`，忽略 `none`，强制套用。

### 4.3 每个请求的处理流程

```
1. 鉴权，确定 user 和 workspace
2. 解析模型：body.model → models 表（is_active），拿到 provider 和 upstream_model
   找不到返回 404 {error:{message:"模型不存在或未开放"}}
3. 估价：pricing.estimate(model, params) → estimateCredits（整数点数）
4. 品牌注入：brand-inject 改写 prompt，必要时追加参考图（见 4.5）
5. 审核：moderation.checkPrompt(prompt)，命中平台黑名单返回 422
6. 冻结：ledger.hold(workspace, user, estimate, jobId)
   余额不足或超出成员上限返回 402：
   {error:{code:"insufficient_credits", message:"点数不足，本次需要 X 点，剩余 Y 点", required:X, balance:Y}}
7. 转发上游：替换 model 为 upstream_model，替换 Authorization 为供应商 Key，透传其余字段
   超时：图片 10 分钟，文本 5 分钟，语音 2 分钟
   客户端断开时中止上游请求（AbortController）
8. 上游成功：
   actual = pricing.actual(model, params, upstreamResponse)
   ledger.settle(job, actual)；实际比冻结的少就退回差额，多就补扣（余额不够时扣到 0，并在 job 上标记 overdraft）
   响应头带上 X-IC-Credits-Charged 和 X-IC-Credits-Balance
   archive.enqueue(job, outputs)：后台上传到 S3，不阻塞响应
9. 上游失败 / 超时 / 客户端取消：
   ledger.refund(job)，job.status = failed，记录 error
   把上游的错误状态码和错误消息透传给前端（前端已有 readStatusError 做中文提示）
```

### 4.4 计价规则（`pricing.ts`，纯函数）

定价存在 `pricing_rules` 表里，每个模型一条，`unit` 字段决定计价方式：

| unit | 估价 | 实际 |
|---|---|---|
| `per_image` | `n × price(size_tier)`。size_tier 按 size 的最长边判断：≤1536 为 `standard`，否则为 `hd`；`auto` 算 `standard` | 按上游实际返回的图片张数 × 单价 |
| `per_second` | `seconds × price` | 等于估价 |
| `per_1k_tokens` | 固定冻结 `hold_credits`（默认 10） | `ceil(in/1000 × price_in + out/1000 × price_out)`，最少 `min_credits`。usage 从 SSE 的 `response.completed` 事件里读，读不到时按冻结额结算 |
| `per_1k_chars` | `ceil(len(input)/1000 × price)` | 等于估价 |

`price` 的结构见 `specs/schema.sql` 中 `pricing_rules.config`（jsonb）的注释。所有点数都是整数，计算时一律向上取整。

### 4.5 品牌注入（`brand-inject.ts`，纯函数）

输入：品牌对象、原始 prompt、能力类型、该模型是否支持编辑（`models.supports_edit`）、原始参考图数量。
输出：新的 prompt，以及需要追加的参考图列表（对象存储里的 key）。

拼接格式（与设计稿 04 右侧"生成时实际注入"的预览完全一致；预览接口 `GET /api/brands/:id/injection-preview` 也调用这个函数）：

```
[品牌] {brand.name}
[风格] {required_terms，用"，"连接}
[色彩] {colors，例如 "主色 #1F3B2D，辅色 #C7A46A"}
[避免] {avoid_terms，用"、"连接}
[参考图] 风格参考 ×{n}          ← 只有实际附带了参考图时才输出这一行
—— 用户提示词 ——
{原 prompt}
```

规则：

- 文本模型（`/responses`）不注入参考图，只把品牌块放到 system 消息的前面。语音和视频只注入文字。
- 图片：如果品牌有勾选了"随生成附带"的风格参考图，并且模型支持编辑：
  - `/images/generations` 会被网关**改写成上游的 `/images/edits` 调用**，品牌参考图作为 `image[]` 附带。
  - `/images/edits` 把品牌参考图追加到用户参考图之后。
  - 用户参考图和品牌参考图加起来不超过 `models.max_reference_images`（默认 8）。超出时少带品牌图，用户图优先。
- 原前端的参考图编号逻辑（`buildImageReferencePromptText`，"参考图片编号：图片1、图片2…"）只覆盖用户的图。品牌参考图在 `[参考图]` 那一行说明"后附 N 张为品牌风格参考，不作为画面主体"。
- 品牌参考图**不计入**计费张数（计费只看 `n`）。

### 4.6 视频任务

- 创建（`POST /videos`）：先冻结点数，转发上游，然后写一条 `video_tasks`（`id = vt_<nanoid>`，`upstream_task_id`，`job_id`），返回 `{id: "vt_…", status: "queued"}`。
- 查询（`GET /videos/:id`）：用 upstream_task_id 去问上游，状态原样返回。
  - 第一次看到 `completed` 时，结算这个 job，并在后台把视频归档到 S3。如果上游返回了 url，就把 url 改写成 `/api/gateway/v1/videos/:id/content`，避免前端直连上游。
  - `failed` 或 `cancelled` 时退款。
  - 同一个任务只能结算或退款一次：用 `generation_jobs.status` 做条件更新来保证幂等。
- 扫描器：每 5 分钟扫一次超过 30 分钟仍是 `held` 状态的视频 job，在服务端主动查一次上游；查到终态就结算或退款；超过 2 小时仍未完成的直接退款，并标记为 `timeout`。

### 4.7 上游供应商

- `providers` 表：`name`、`base_url`、`api_key_encrypted`（AES-256-GCM）、`api_format`（MVP 只支持 `openai`）、`is_active`。
- `models` 表：`id`（对外名称，例如 `gpt-image-2`）、`capability`、`provider_id`、`upstream_model`、`supports_edit`、`max_reference_images`、`is_active`、`sort`。
- 同一个对外模型可以配置多个供应商做故障切换（`model_routes` 表，按 `priority` 排序）。上游返回 5xx 或超时时，按顺序换下一个供应商。**只有在还没向客户端写出任何响应时才能切换**；流式响应一旦开始就不切换。

## 5. 点数账本（`billing/ledger.ts`）

### 5.1 设计

- `credit_buckets`：点数桶。字段有 `kind`（`subscription` / `purchase` / `gift`）、`granted`、`remaining`、`expires_at`（null 表示不过期）。
- `credit_transactions`：账本流水，**只追加、不修改**。字段有 `type`（`grant` / `hold` / `settle` / `refund` / `expire` / `adjust`）、`amount`（正数为增加，负数为减少）、`breakdown`（jsonb，记录涉及哪些桶、各多少）、`job_id`。
- `generation_jobs`：每次网关请求一条。字段有 `status`（`held` → `succeeded` / `failed` / `timeout`）、`estimate_credits`、`charged_credits`、`hold_breakdown`。
- 余额 = 当前工作区所有未过期桶的 `remaining` 之和。界面上的"剩余点数"就是这个值。

### 5.2 操作（每个操作都在一个数据库事务里完成）

- **hold(ws, user, amount, job)**
  1. `SELECT … FROM credit_buckets WHERE workspace_id=$1 AND remaining>0 AND (expires_at IS NULL OR expires_at>now()) ORDER BY (kind='subscription') DESC, expires_at NULLS LAST, created_at FOR UPDATE`
  2. 如果是 member，检查成员上限：本月该成员的 `charged_credits`（succeeded 的 job）加上 `estimate_credits`（held 的 job）再加 `amount`，不能超过 `workspace_members.monthly_cap`。
  3. 按排序依次从各桶扣减，直到凑够 `amount`；凑不够就整个事务回滚并返回 402。
  4. 写 job（`status = held`，`hold_breakdown`）和一条 `hold` 流水。
- **settle(job, actual)**
  - 条件更新：`UPDATE generation_jobs SET status='succeeded' … WHERE id=$1 AND status='held'`。影响 0 行说明已经处理过，直接返回。
  - `actual < hold` 时，按 `hold_breakdown` 的逆序把差额退回原来的桶。
  - `actual > hold` 时，再按 hold 的规则补扣；不够就扣到 0，并标记 `overdraft = true`。
  - 写一条 `settle` 流水。
- **refund(job)**：同样用条件更新保证幂等，把 `hold_breakdown` 原样退回各桶，写一条 `refund` 流水。
- **grant(ws, kind, amount, expires_at, reason)**：管理员加点、兑换码、注册赠送、套餐月度发放都走这个操作。

### 5.3 套餐与月度重置

- `workspaces` 表上有 `plan`（`free` / `team` / `enterprise`）、`plan_monthly_credits`、`period_start`、`period_end`。
- 扫描器每小时检查一次：对 `period_end <= now()` 的工作区，先把旧的 subscription 桶的剩余点数清零（写 `expire` 流水），再发放一个新桶（`expires_at` = 新的 period_end），然后推进周期。
- MVP 里套餐由管理员在后台设置；在线订阅放到第 2 期，届时通过 `PaymentProvider` 接口接入。

### 5.4 兑换码

- `redeem_codes` 表：`code`（16 位，大写字母和数字，排除 0/O/1/I）、`credits`、`kind`（`purchase` 或 `gift`）、`max_uses`、`used_count`、`expires_at`。
- `POST /api/billing/redeem {code}`：只有工作区 owner 能兑换。写 `redeem_code_uses`，然后调用 grant。

## 6. 品牌套件

- 表：`brands`、`brand_colors`、`brand_assets`。`brand_assets.kind` 取值 `logo` / `sku` / `style_ref`；`style_ref` 类型有 `attach_on_generate` 布尔字段。
- 文件上传：前端先调 `POST /api/uploads/presign {kind, mimeType, bytes}` 拿到 S3 预签名 PUT URL，直接上传到 S3，再把返回的 `objectKey` 提交给业务接口。限制：单张图片 ≤ 20MB，只允许 png、jpg、webp。
- 读取：业务接口返回的图片地址都是 `/api/files/<objectKey>`。这个接口会校验当前用户的工作区权限，然后 302 跳转到一个 10 分钟有效的预签名 GET URL。
- **画布里使用品牌素材**：从侧边栏"品牌"tab 拖一个 SKU 到画布时，前端先 `fetch` 这张图，再走原有的 `uploadImage(blob)` 存进 IndexedDB，生成普通的图片节点。这样画布数据结构不变，导出和 WebDAV 同步照常可用。

## 7. 行业模板

### 7.1 数据格式

完整定义见 `specs/template.schema.json`，示例见 `specs/template-example.json`（电商主图套图）。要点：

- 模板的主体是 `ops: CanvasAgentOp[]`，直接复用 `web/src/lib/canvas/canvas-agent-ops.ts` 的指令集。
- 节点 id 写成模板内的局部 id（例如 `"sku"`、`"scene"`）。坐标相对于模板原点。
- 变量占位用 `{{var.<key>}}`，可以出现在 `metadata.content`、`metadata.prompt`、`metadata.composerContent`、`title` 中。
- 引用上游节点沿用原项目的 `@[node:<局部id>]` 语法，实例化时会重映射成新的节点 id。
- `variables[]` 定义变量：
  - `type: "text"`：直接替换文本。
  - `type: "image"`：用户上传图片，或从品牌 SKU 里选一张。实例化时这张图会作为 `bindNode` 指定节点的图片内容。
  - `type: "select"`：下拉选择，替换文本。
- `steps[]` 定义运行步骤：每一步包含 `label`、`nodeIds`（这一步要运行的生成节点）、`estimate`（用于展示的预估点数）。"运行全部"按 steps 的顺序执行。

### 7.2 实例化（前端：`web/src/lib/templates/instantiate.ts`，纯函数，必须写单测）

```
instantiateTemplate(template, values, origin) → { ops: CanvasAgentOp[], idMap }
1. 给每个 add_node 的局部 id 生成新 id（nanoid），得到 idMap
2. 遍历所有 op 的字符串字段：
   {{var.x}} 替换成 values.x
   @[node:local] 替换成 @[node:idMap[local]]
3. add_node 的 position 加上 origin（当前视口中心减去模板包围盒的一半）
4. connect_nodes 的 fromNodeId / toNodeId 按 idMap 替换
5. image 类型变量：先把图片存进 IndexedDB（uploadImage），再在对应 add_node 的 metadata 里写入 storageKey、content、naturalWidth、naturalHeight、mimeType、bytes
6. 最后追加一个 group 节点把整组节点包起来（标题："模板 · {template.name}"），再加一个 select_nodes
7. 在 group 节点的 metadata 上写 templateRun: { templateId, stepIndex: 0, idMap }，供运行条读取
```

然后调用画布页面的 `applyAgentOps(ops)`（来自 `useAgentBridge`）。这样自动支持撤销。

`CanvasNodeMetadata` 需要新增两个可选字段：`templateRun?`（只放在 group 节点上）和 `brandKit?: boolean`（生成节点上，设为 `false` 表示这个节点不套用品牌）。

### 7.3 运行全部

- 画布顶部运行条（`components/canvas/canvas-template-run-bar.tsx`，新文件）：读取当前选中节点或视口内带 `templateRun` 的 group，显示模板名、当前步骤、预计点数。
- 点击"运行全部"：先弹出确认框，显示总预估和当前余额。确认后依次执行每个 step：对 step 里的每个节点调用 `generateNodeRef.current(nodeId, mode, prompt)`；同一个 step 里的节点并发执行，step 之间串行；每完成一步就更新 `stepIndex`。
- 任一节点失败时：停在这一步，运行条显示"第 N 步失败，可重试"。已经成功的步骤不回滚。
- **模板里的生成目标用"空的 image 节点"，不要用 config 节点。** 原有的 `handleGenerateNode` 有两种行为：
  - 对 config 节点生成时，会**新建**一个结果节点，再从 config 连线过去。下游节点没法在模板里预先连到这个新节点。
  - 对空的 image 节点生成时（`project.tsx` 里 `isEmptyImageNode` / `reuseImageNode` 那个分支），结果会**原地写回这个节点**。

  所以模板用"带 prompt、size、count 元数据的空 image 节点"作为每一步的生成目标，下一步的节点就能预先连到它上面，并通过 `buildNodeGenerationContext` 自动读到上游的图片和文本。实现前请在真实画布上验证这个行为；如果和预期不符，在 `handleGenerateNode` 里加一个最小分支来支持，并在 PR 里说明。

### 7.4 存为团队模板

- 入口：选中若干节点后，在右键菜单或选择工具栏里选"存为团队模板"。
- 弹窗填写名称、分类、描述，并勾选哪些节点作为变量（文本节点对应 text 变量，图片节点对应 image 变量）。
- 前端把选中的节点和它们之间的连线转换成 ops：坐标减去包围盒左上角；图片节点上传到 S3，作为模板的默认示例图。提交到 `POST /api/templates`。
- steps 自动生成：对生成配置节点按连线做拓扑排序，同一层级作为同一个 step。

`server/src/db/seed.ts` 写入 6 个官方模板（名称见 PRD 4.1）。每个模板都要完整可运行：节点、连线、提示词都写好。可以参照 `specs/template-example.json` 的写法。

## 10. 部署（docker-compose.yml 需要改写）

服务清单：`web`（nginx，静态文件 + 反向代理 `/api/` 到 server）、`server`（bun）、`postgres:16`、`minio`（外加一个初始化 bucket 的一次性容器）。

- `nginx.conf` 增加 `location /api/ { proxy_pass http://server:8787; proxy_buffering off; proxy_read_timeout 900s; client_max_body_size 100m; }`。关闭缓冲是为了 SSE 和大文件能流式传输。
- server 启动时自动执行 drizzle 迁移，然后执行幂等的 seed。
- 保留原来"只跑 web"的部署方式：`docker-compose.web-only.yml`。

## 11. 安全清单

- 上游 Key 加密存储；任何接口和日志都不能返回明文 Key，管理后台只显示后 4 位。
- 网关请求体有大小上限（100MB）；单用户限流（MVP 用内存令牌桶：每分钟 60 次生成请求）。
- `/api/files/*` 必须校验 objectKey 属于当前工作区（objectKey 的前缀就是 `ws/<workspaceId>/`）。
- 上传接口校验 mimeType 和大小，预签名 URL 的有效期是 5 分钟。
- 管理后台的接口统一挂 `requirePlatformAdmin` 中间件。
- 原项目的远程插件、自定义调用脚本会在浏览器里执行第三方代码。平台模式下建议默认只允许官方插件注册表，关于这一点的提示写进安全文档 `docs/content/docs/support/security.mdx`。
