# 平台安全与数据边界

平台供应商 Key 只在服务端使用，通过 `APP_SECRET` 派生的密钥进行 AES-256-GCM 加密后保存。前端模型目录与管理接口不返回明文 Key。口令使用 Argon2id，Cookie 会话为 HttpOnly；写操作校验 Origin，工作区业务接口核对成员权限，管理接口核对平台管理员身份。

## 本地与服务端数据

| 数据 | 存储位置 |
| --- | --- |
| 账号、工作区、品牌、团队模板、账本和任务 | PostgreSQL |
| 品牌/模板图片和平台生成归档 | 私有 S3/MinIO 桶 |
| 画布项目、画布素材、工作台历史 | 浏览器本地；可自行配置 WebDAV |
| 自带 Key 渠道配置 | 浏览器本地，由浏览器直连供应商 |

退出平台账号不会自动删除本机画布或自带 Key 配置。同一浏览器配置文件中的本地数据不等同于后端工作区隔离；在共享电脑上应按实际需要导出并清理本地数据。

临时上传绑定工作区、用户、用途、内容类型与大小；最终素材复制到独立对象，旧预签名 PUT 不能覆盖它。读取文件先校验会话与归属，再签发临时地址。预签名地址持有者在其有效期内可以访问对象，因此不要把完整签名 URL 作为永久公开链接。每个环境使用独立桶；清理队列按数据库地址命名空间隔离，同一数据库的所有服务实例使用一致、显式的数据库地址。

## 插件与调用脚本

原项目的第三方节点插件和自定义调用脚本运行在网页上下文中。安装的代码能够读取本地数据、访问页面接口，并以当前会话发起请求；HttpOnly 防止脚本直接读取会话 Cookie 的值，但不会阻止同源脚本使用会话权限。只安装你信任的代码，并审查来源及更新。

平台网关隐藏供应商 Key，不等于把第三方插件隔离在沙箱中。平台生成渠道和自带 Key 渠道的数据路径不同；自带 Key 仍可被受信任页面代码访问。

## 部署与维护

`TRUST_PROXY` 默认关闭。生产编排只有 nginx 暴露应用入口，后端不发布端口；nginx 覆盖 `X-Real-IP` 后才启用可信代理。不要把该配置直接用于公开暴露的 Bun 服务。线上使用 HTTPS，并让 `APP_ORIGIN`、浏览器地址和对象存储公开端点保持一致。

备份 PostgreSQL、S3 对象和 `APP_SECRET`。更换 `APP_SECRET` 前需要制定现有加密供应商配置的迁移方案；仅替换环境变量会使旧 Key 无法解密。不要将 `.env`、数据库备份、预签名 URL 或未脱敏日志提交到仓库。

当前验收包括密钥明文扫描、转义 JSON/SSE 响应脱敏、会话/工作区竞争、账本幂等与存储归属测试。这些证据有明确范围，不能承诺未来任意插件、供应商响应或运维日志永不泄露。验收限制和部署步骤见[平台模式部署](/zh-CN/docs/overview/platform-deployment)。原项目漏洞报告流程见[安全报告](/zh-CN/docs/support/security)。
