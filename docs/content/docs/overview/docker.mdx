# Docker Deployment

## Build this checkout in frontend-only mode

```bash
docker compose -f docker-compose.web-only.yml up -d --build
```

Open `http://localhost:3000`.

The main Compose file now enables the workspace platform. For accounts, billing, brands, and templates, configure `.env` and follow [Platform Deployment](/docs/overview/platform-deployment). The upstream published image is the original frontend and does not include this branch's platform extension.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The frontend-only application container runs nginx serving a Vite build. Canvases, My Assets, generation history, and BYOK keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. Platform mode additionally persists database and object-storage data. The separate documentation application uses Next.js.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
