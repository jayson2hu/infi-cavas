## 结论

**通过（修复后）。** 代码质量很高：数据库与规格完全一致，账本、权限、密钥脱敏都很严谨。但原实现**无法在真实环境部署**：有 3 个部署级缺陷，Codex 本机缺少 Docker、不能监听 HTTP，所以没测出来。这 3 个已全部修复，并在真实 `docker compose` 部署中验证通过。

## 验收环境

- 一台干净的 Linux 机器。用随机生成的密钥，从仓库的 Dockerfile 构建镜像，再执行 `docker compose up`，起 web（nginx）、server、PostgreSQL 16、MinIO（pgsty 分支）四个服务。
- 浏览器和 curl 都经 nginx 的 `http://localhost:3000` 访问，走真实 HTTP；不再是 `app.request` 进程内调用。
- 真实供应商：用户提供的测试渠道，模型 `gpt-image-2`。受控假上游只用于模拟故障。
- 仅为适配验收机器的出网代理，构建时额外注入了代理证书；仓库里的 Dockerfile 和 compose 文件没有为此改动。

## 待决策

- **I-037（P2）注册送点数可被批量套取**：注册接口没有限流，也不验证邮箱，每次注册都送 200 点。接上付费供应商后，这就是直接的成本风险。两种方案：① 注册按 IP 限流；② 邮箱验证通过后再发放赠送点数。都涉及新的边界值，需要你确认后再实现。
