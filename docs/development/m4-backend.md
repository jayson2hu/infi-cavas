# M4 模板后端、共享语义校验与官方种子

先阅读权威 `specs/schema.sql`、`specs/openapi.yaml`、`specs/template.schema.json`、`specs/template-example.json`、交付包模板章节和 `m4-plan.md`，再阅读真实会话/工作区权限、品牌编辑权限、S3 上传、对象清理、定价与种子代码。数据库保持原规格 23 张表，不增加字段或迁移；画布继续主要保存在浏览器本地。

## 实现与原文件修改理由

- 新增 `shared/template.ts`：前后端共用模板类型和无数据库依赖的语义校验。检查变量唯一性、图片绑定、select 默认值、局部 ID、占位符、节点引用、分组关系、连线环路、生成类型和步骤依赖。直接/间接依赖的生成节点必须属于更早步骤，不能同一步并行读取尚未完成的输出。
- 新增 `server/src/templates/validation.ts`：AJV2020 直接编译权威 JSON Schema，再调用共享语义校验；错误返回 422 和字段路径。拒绝额外操作字段、浏览器临时地址、本地 storageKey、运行结果、账号上下文、密钥及私有渠道模型 ID。模板模型保存裸 ID，前端显式匹配实际可用渠道。
- 新增 `server/src/routes/templates.ts`：列表支持类别、范围和关键词，列表不含 body；详情包含 body 与 canEdit。团队模板限当前工作区，owner/admin 或当前工作区任一品牌的 editorUserIds 成员可创建、修改、删除。普通成员可以读取和使用；平台管理员不能因此访问其他团队模板。官方模板向各工作区开放，仅平台管理员可修改、删除。写操作在工作区、成员、模板锁内重新检查权限；官方写权限重新读取数据库。use 在事务中原子加一，不创建生成任务、不访问账本。
- 新增 `server/src/templates/storage.ts`：图片和封面复用 M3 真实字节/MIME/尺寸、签名元数据、上传人、工作区和用途校验。引用固化到当前模板最终路径；仅保留当前模板旧 body/封面实际引用的最终对象，不接收其他模板的最终路径。图片节点 content 与图片变量 default 指向同一上传源时共用同一个最终对象。上传副本替换后补充验证过的 naturalWidth/naturalHeight/mimeType/bytes。
- 新增 `server/src/templates/official.ts`：六个完整官方模板，种子初次写入时按当前 pricingRules 估价。通过固定 ID 与 onConflictDoNothing 保留运营修改、使用次数和发布状态。
- 修改 `server/src/app.ts`：挂载模板路由，继续统一使用会话、工作区及 Origin 校验。
- 修改 `server/src/db/seed.ts`：模型/定价与六个官方模板在同一事务内初始化，缺少定价时回滚，不写不完整种子。
- 修改 `server/src/routes/uploads.ts`：官方图片独立放在 `official/templates/<templateId>/`。请求者须有有效会话和工作区；只有仍发布且当前 body/封面引用的官方对象可读取。团队图片沿用路径工作区成员校验；内部清理文件不可通过文件接口读取。
- 修改 `server/src/lib/object-cleanup.ts`：复用既有扫描器，增加模板对象任务。读取锁定后的当前 body/封面，仅删除已解除引用的候选对象；创建成功或修改回滚保留对象，删除/替换提交及创建失败后回收对象。新增数据库命名空间隔离，详见 I026。
- 修改 `server/tests/brands.integration.test.ts`：为共享清理器增加跨数据库环境隔离回归；新增 template-validation 与 templates.integration 测试覆盖 M4。没有修改权威 schema、OpenAPI 或数据库结构。

## 固化、回滚与清理隔离

团队最终路径为 `ws/<workspaceId>/templates/<templateId>/img_<id>.<ext>`；官方最终路径为 `official/templates/<templateId>/img_<id>.<ext>`。临时上传仍在工作区 uploads 前缀，客户端旧 PUT 授权不覆盖最终对象。每次最终写入前持久化清理任务；失败时按数据库当前引用回收已写入副本，原临时上传保留以便重试。成功后删除临时上传；临时删除失败记录事件，不破坏已经提交的模板。

I026：测试库与开发库可能共用存储桶，原全局 `internal/cleanup/` 扫描会把其他数据库的任务误判为已删除目标。现在任务前缀为 `internal/cleanup/<sha256>/`，hash 输入仅含规范 hostname、port（默认 5432）和解码后的数据库 pathname；用户名、密码和连接选项不参与。当前进程只扫描、执行自己的前缀，不扫描或迁移旧全局任务。已有本机验收任务已在各自清理步骤完成；本次不作跨环境旧任务推断。

部署建议每个环境使用独立 bucket。同一数据库的所有实例应使用一致、含明确数据库名称的 DATABASE_URL 地址；主机别名不能当作自动识别的同一数据库。清理命名空间是共享桶下的误删防护，不能代替存储凭据和环境隔离。清理仍是 PostgreSQL 与 S3 间的可恢复流程，不是跨服务原子事务；失败任务由原 5 分钟扫描继续恢复，不新增表、环境变量、重试次数或定时器。

## 六个官方流程

| ID | 流程 |
| --- | --- |
| tpl_ecom_main_set | 沿用权威示例：场景图 5 张，再适配 3 个尺寸；默认价格共 40 点（两步各 20） |
| tpl_product_detail_long | 文案结构 → 3 个详情板块 → 1024×3072 详情长图 |
| tpl_short_video_storyboard | 分镜与旁白文本 → 3 张分镜图 → 3 段 4 秒短片 → 旁白配音 |
| tpl_brand_campaign_poster | 活动文案 → 竖版海报和横版宣传图 |
| tpl_social_xhs_set | 种草文案 → 封面和两页组图 |
| tpl_store_materials | 门店文案 → 海报、台卡和横幅 |

产品图作为图片变量输入，可由前端选择当前品牌 SKU；种子不夹带静态示例素材或账号业务数据。音视频完整流程保留，当前真实供应商缺少的能力记录为 I024，不能用图片流程替代后宣称满足。模型 ID 仍为交付包默认值，未配置可用渠道时由前端明确阻止运行，不静默替换模型。

## 规格差异与估价政策

- SQL 指定 `estimate_credits` 由保存时 `body.steps[].estimate` 求和；后端严格遵循，不把 GET 改成隐式重新定价。前端保存时提供实际配置的步骤估计，运行界面按当前模型价格另行展示。种子首次创建也按当时定价计算；重复 seed 不覆盖运营编辑。示例 `1:1` 仅在种子估价时按 1024×1024 解释。
- PATCH 接受 `coverObjectKey: null` 清空封面，这是对原 OpenAPI 非空字符串的明确扩展；未提供该字段则保留封面。
- 权威 Schema 的 op 分支未禁用额外属性；服务器进一步只允许规格声明的操作字段，防止藏入运行命令或私有字段。metadata 仍支持可序列化的业务参数，但拒绝运行状态、密钥、账号上下文与本地引用。`/api/files/` 素材地址仅允许图片节点 content 或图片变量 default，经归属验证和固化后保存；已有音视频结果不作为模板内容保存。
- 共享语义校验检查生成步骤只针对对应的 text/image/video/audio 结果节点。config 转换为结果节点由前端序列化器负责；后端不执行画布命令，也不自动生成或扣点。
- I029：官方 DELETE 保留原 ID 并设置已有字段 isPublished=false，返回仍为 204；列表、详情、修改、使用和官方文件读取随后不可用，启动 seed 遇到同 ID 不会重新创建。团队 DELETE 仍物理删除。清理器锁定模板后，只保留已发布官方或仍存在团队模板的当前引用；下架提交后回收原图片/封面，下架回滚或清理等待期间已重新发布则保留当前引用。当前 API 不提供重新发布已删除官方模板的功能，不增加字段或迁移。

环境为 Bun 1.3.14、真实 PostgreSQL 16 测试库与 S3rver。后端测试直接调用 Hono app.request；上游响应来自可注入 fetch，没有启动额外 HTTP 监听。

- `bun run typecheck` 通过。
- 首次 M4 专项校验与集成共 14 项、183 次断言通过；随后补充隐藏文件引用拒绝与清理环境隔离。
- M4 阶段完整 `bun test`：16 个文件，93 项通过、0 失败、878 次断言。覆盖 23 表规格等价、M1–M3 鉴权/账本/网关回归、六种子语义、模板 CRUD 和跨工作区隔离、编辑者撤权竞态、并发 use 计数且不扣点、422 字段路径、图片/default 去重、PUT 重放不改最终对象、跨上传人/用途/模板拒绝、第二张图片失败回收前一副本、官方文件授权、删除回滚/故障恢复/幂等、种子定价和运营编辑保留。
- M5 最终复核的 I029 修复后，类型检查与完整后端回归再次通过：17 个文件，98 项、936 次断言、0 失败。新增回归证实固定官方种子 ID 经 DELETE 与 seed 后仍下架，图片/封面已回收，所有读取/修改/使用入口不可见；团队仍物理删除。下架回滚保留对象，S3 删除故障保留恢复任务；清理等待模板行锁期间发布状态改变时，按提交后的最新状态保留有效引用。固定种子测试结束恢复完整原记录。
- I026 专项证实同库地址的默认端口、编码与凭据轮换得到相同前缀；不同数据库或端口得到不同前缀。实际 S3 扫描恢复当前数据库任务，同时保留另一数据库的任务和对象，直接执行外部命名空间任务也拒绝。
