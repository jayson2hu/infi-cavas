# M1 权限与登录限流复核

已读文件：`server/src/routes/auth.ts`、`workspaces.ts`、`middleware/session.ts`、`origin.ts`、`rate-limit.ts`、`billing/ledger.ts`、环境配置、现有集成测试，以及权威 OpenAPI 与 SQL 的账号/工作区章节。

## 修复

- 登录限流先前只使用连接 IP，在 nginx 反代部署中会让所有用户共用代理的一个额度。新增 `resolveClientIp` 和默认关闭的 `TRUST_PROXY`；只在明确可信的反向代理部署中采用合法的单一 `X-Real-IP`，直连忽略该头，无效值回退连接 IP。生产部署必须确保 server 不能被公网直达，并由 nginx 覆盖 `X-Real-IP`。
- 工作区改名、成员角色/上限、移除成员和创建邀请先前在事务外读取操作者角色，撤权与写入并发时可能执行已失去授权的操作。所有这些写入现在先锁工作区，再在事务内重新读取并锁住操作者成员关系，之后操作目标成员。保留原权限检查作为快速拒绝。
- 接受邀请先查询其工作区，再按工作区→邀请的顺序加锁，保持与其他成员操作一致的锁顺序。
- 成功登录不再清除同 IP 的失败计数，避免使用已知账号反复重置五分钟失败窗口。
- 邀请接口允许 OpenAPI 中约定的空请求体，按默认 `member` 角色创建；非空的非法 JSON 仍返回错误。

原有上游文件未修改；改动均为本次二开新增的后端文件。不改变 API 路径、角色能力或权威表结构。

## 验收

新增 IP 纯函数测试覆盖可信代理的 IPv4/IPv6、不同客户端隔离、直连伪造请求头、无效 IP 回退。

新增真实 PostgreSQL 并发回归：使用工作区行锁阻塞在途请求，通过 `pg_stat_activity` 确认已等待后提交撤权；角色修改、改名、删除成员和邀请均必须返回 403，数据库不得产生未授权写入。测试不靠 sleep，不启动 HTTP 监听，只清理自己创建的用户和工作区。

执行 `bun run typecheck` 通过；执行 `bun test tests/client-ip.test.ts tests/workspace-security.integration.test.ts tests/auth.integration.test.ts`：12 项通过、0 失败、121 次断言。并发测试使用本机真实 PostgreSQL 16.6；未启动 HTTP 监听。

补充 `auth-security.integration.test.ts` 的两项回归也已通过：9 次失败→1 次成功→第 10 次失败后仍触发 429；空请求体邀请创建成功且数据库角色为 member。

## M2 锁顺序建议

所有账本事务沿用工作区→成员/任务→桶的锁顺序；settle/refund 先只读任务归属，再锁工作区与任务，避免任务→工作区反向加锁。成员额度变更与 hold 共用工作区锁，使月度上限检查和冻结具备一致性。兑换码操作也应先锁工作区，再锁兑换码；所有扣点与退款路径都须遵守同一顺序。

## 管理员首次部署

现有规格按 `ADMIN_EMAILS` 与注册时自报的邮箱匹配授予平台管理员，MVP 没有邮箱所有权验证。因此，部署者必须先在仅自身可访问的环境完成管理员账号注册，再开放公网注册；不能让尚未注册的管理员邮箱名单先暴露在公开注册服务中。此处记录规格带来的启动条件，没有擅自新增邮件验证接口或改变账号规则。
