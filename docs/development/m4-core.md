# M4 模板转换与运行核心

已读真实画布节点、连线、生成配置、Agent操作和权威模板规格后实现。核心位于 `web/src/lib/templates/`，不访问网络、数据库或浏览器存储。

## 实例化与保存

- `instantiateTemplate` 接收外部准备好的图片元数据；验证变量与选项，单次替换变量及节点引用，重建全部ID、连线、嵌套组和外层模板组。连接操作统一排在节点创建后。
- 图片上传由页面层完成；未准备好的云端图片引用不能直接进入本地画布。ID工厂可注入，碰撞明确报错；原始模板不被修改。
- `serializeTemplate` 保留选择范围内的组后代、输入、内部连线及相对位置。生成配置与其历史结果归并成一个空生成目标，下游引用指向这个目标，防止把历史结果误存为额外付费步骤。
- 保存有效生成参数，节点显式设置优先于全局默认值；清除运行状态、历史输出、任务ID、浏览器存储位置、账号上下文及渠道凭据。输入图片仅保留经服务端验证的文件引用。
- 按依赖拓扑构造步骤，同层同模式节点并发。循环、外部节点引用、无法重建的变量和没有生成步骤均明确拒绝。

## 运行

`runTemplateSteps` 等待每步所有节点返回真实成功结果后才进入下一步；每个节点成功后立即保存进度，同一步失败时保留成功同伴，续跑跳过这些已完成节点。停止后不再发起下游节点，完整重跑通过显式重置进行。

画布调用方在生成结束后同步节点状态与引用，再读取下游依赖；强制原位生成，避免用户普通节点的另建结果设置破坏模板引用。实际图片批次、文本流、视频和语音行为由六套浏览器流程继续验证。

## 验证

执行 `bun test tests/templates.test.ts`：12项通过，58断言，无失败。覆盖权威电商示例、单次替换、原型同名ID和变量、嵌套组、前置连线、图片准备、保存归并、有效参数、循环、并发中间进度、失败续跑和停止。最终全量检查与浏览器证据分别记录，不能以纯函数测试替代实际生成验收。

## 原文件修改理由

`web/src/constant/canvas.ts` 从新增的 `canvas-dimensions.ts` 复用原始尺寸常量，避免纯转换通过画布常量间接加载浏览器和i18n模块；尺寸值保持一致。
